## 範圍只限這次會話真正用過的 skill 和工具

發現只路由到這份對話記錄用過的 skill、工具或 MCP。下面任一情況出現，就算這個 skill 用過了：對話記錄裡有一次 `read` 或 `skill` 呼叫，讀的是它的 `SKILL.md`（在 `~/.agents/skills/` 或專案 `.opencode/skills/` 下）；某次 `subagent` 提示詞寫了它的路徑；或者某次工具呼叫（`shell`、`grep`、MCP 等）對得上它文件裡的命令。父代理沒開啟過的 skill，推測性路由不算。

兩種發現形態有效：

- 父代理呼叫了這個 skill，你在它正文裡發現了真實缺口。路由到該 skill 的相關章節。
- skill 在目錄裡看得到，但在本該幫忙時沒有觸發。改它的 description，讓以後的代理能選中它。路由寫成 `tune description: <skill path>`。

沒呼叫過、也不是漏觸發候選的 skill，丟掉。

每條可複用的經驗都列出來。每條包含：

- Principle: 一句話，寫出能推廣開的規則本身。不要只貼個標籤，也不要點名充數。
- Evidence: 對話記錄裡它浮出來的那個時刻（輪次，或一小段原文）。
- Routing: 最相關的現成 skill（對話記錄裡出現的那個 `SKILL.md` 路徑），或者該觸發卻沒觸發時寫 `tune description: <skill path>`，或者沒有現成 skill 真正接得住時寫 "new skill: <kebab-name>"。

跳過瑣碎的（錯別字、工具重試、機械性的準備），也跳過父代理已經照著做的 skill 裡顯而易見的內容。跳過會隨程式碼變化而過時的實現細節：具體 SHA、當前檔案路徑、版本號、精確位元組數。只提出程式碼變了也還成立的原則和模式。
